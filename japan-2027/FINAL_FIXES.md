# 일본 2027 여행 지도 — 4차 통합 보완

기준: `7c9f511fab378d4101782b72e0395774ebb04a7b` (작업 시작 시 최신 main). 확인일 2026-10-25, 시간 표기는 일본/한국 현지 UTC+9.

이 문서는 코드·자료의 변경 근거와 검증 방법을 기록한다. 최종 main SHA, GitHub Actions 및 공개 Pages 재검증 결과는 배포 후 최종 응답에서 별도로 확인한다. 이 문서만으로 배포 성공을 뜻하지 않는다.

## 1. 배포와 검증 순서

1. 로컬 함수·일정 검사 및 실제 앱 브라우저 시나리오 실행.
2. `codex/japan-final-qa` 브랜치에서 GitHub Actions 실행.
3. 성공한 동일 커밋만 main으로 이동. 기존 Pages 자동 배포의 완료 확인.
4. 공개 URL에서 1~4차 브라우저 회귀 검사와 모바일 화면 재확인.

CI는 push/PR 때 자동 실행한다. 기존 branch-based Pages의 발행 원본 설정 변경은 연결 도구가 지원하지 않으며, 브라우저의 저장소 설정 화면도 로그인되지 않아 접근 불가였다. 따라서 **향후 모든 main 변경을 CI가 선행 차단하도록 저장소 설정까지 바꿨다고 주장하지 않는다.** 이번 반영은 검증 브랜치 통과 뒤 같은 SHA를 main으로 옮기는 순서로 처리한다.

## 5. P3 — 저장·성능·검사

- 시간표는 지연 로딩 유지. 같은 파일 중복 요청 합치기. 메모리 LRU6파일·직렬화 UTF-16 추정16MiB 상한(실제 JS heap 측정값 아님). 현재 탑승 자료는 별도 유지.
- 오프라인 시간표는 최근12파일+현재 탑승 파일을 보존. 메모리와 영구 캐시 분리, 빌드 버전별 무효화. 초기102파일 일괄 다운로드 없음.
- Cache API, 사용할 수 없으면 IndexedDB로 공개 일정 JSON/경로/최근 시간표 저장. GPS 관측값은 저장하지 않는다.
- HTTPS 서비스워커는 앱 코드/스타일/폰트/로고를 저장. 배경 타일을 대량 저장하지 않는다. 선택 대체안/패스/예약/탑승 기록은 기존 브라우저 저장 유지.
- 저장 자료 우선 표시·연결 시 캐시 갱신. 통신 실패 시 기존 자료 유지·오프라인/마지막 갱신 문구. 첫 방문의 미다운로드 지역은 오래된 기본 자료를 최신으로 가장하지 않고 확인된 지역만 표시한다.
- 저장소 사용 불가·용량 오류가 정상 온라인 데이터를 막지 않도록 처리한다.
- `node --test tests/*.test.cjs`, `node scripts/japan-qa.cjs`, JS 구문 검사. 별도 검증 UI에32통합/40모바일/20상태/31정확성 시나리오 제공.
- CI는 순수/데이터/구문 검사와 Chromium 네 브라우저 스위트를 실행한다. 추가로 네트워크 차단 후 실제 새로고침 및 첫 방문 JSON 일부 실패를 검사한다. CI 코드 자체를 로컬 cloud browser 테스트 대신 실행했다고 하지 않는다.

## 12. 남은 제한

실시간 열차 지연/운휴/실제 차량 식별 서비스는 제공하지 않는다. 시간표와 일정 추정은 GPS·사용자 확인과 구분한다. GPS는 터널·실내·백그라운드 갱신을 보장하지 않는다. 지도 복원/대표점/개략선은 현장 길찾기를 대신하지 않는다. 일부 비용·식당 정보·예약 회차는 미확정이다. 오프라인은 미리 저장된 자료에 한하며 배경 타일·외부 공식 사이트는 통신이 필요할 수 있다. 저장소가 거부되면 온라인 표시만 가능하다.

향후 CI와 branch-based Pages의 강제 연계는 저장소 관리자 설정이 필요하다. 이 변경의 검증 브랜치/최종 SHA/실제 배포·공개 재검증 결과는 최종 응답을 따른다.
