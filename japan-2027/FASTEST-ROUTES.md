# 최단시간 우선 경로 (2026-11-11)

활성 2027-01-08–22 일정의 철도 이동 50개 중 출발 시각과 참고 시간표가 있는 43개를 다시 계산한다. 30개는 노선·승하차역이 바뀌고 13개는 같은 경로의 시간을 다시 계산했다. 5개 공항·지정 직통·관광 교통과 출발 시각이 미정인 2개는 기존 경로를 유지한다. 이 숫자는 대체안도 포함한다.

## 계산 계약

- 목적지까지 **가장 이른 도착**이 우선이다. 가격이나 환승 횟수 때문에 더 늦게 도착하는 경로를 고르지 않는다. 도착 시각이 같을 때만 승차 횟수, 보행 시간을 비교한다.
- 장소에서 역까지의 보행, 열차 대기, 환승 여유, 열차 시각, 마지막 역에서 목적지까지의 보행을 합산한다. 선형 길이를 열차 속도로 나눈 값을 시간표로 사용하지 않는다.
- 역 접근은 직선 반경 1.5km 안의 가까운 5개 역명 그룹과 기존 검토 보행 접근로를 비교한다. 직선 3km 이하 장소는 저장 보행로의 직접 도보도 비교한다. 탐색 시간은 출발 후 6시간으로 제한한다. 모든 버스·택시·모든 철도·모든 역 출입구를 포괄하는 전역 최적화는 아니다.
- 동일 유료 구역의 노선 변경은 최소 3분, 구역 간 변경은 최소 6분에 대표 좌표 보행 추정을 반영한다. 신칸센 환승은 12분, 일반 승차 여유는 1분이다. 실제 승강장·출입구별 이동 시간은 확인하지 않았으므로 추정으로 표시한다.
- 직통은 원본의 명시적 열차 연결만 인정한다. 분기 열차를 잘못 연결하거나 환승을 직통으로 표시하지 않는다. 자정 이후 시각과 일본 공휴일을 구분한다.
- 노선 선형은 기존 검증 좌표를 출처의 정차 순서에 맞춰 자른다. 매칭되지 않는 선형은 새 직선 철도로 대체하지 않고 기존 계획을 유지한다.
- 늘어난 이동 시간이 다음 일반 일정과 겹치면 방문 순서·체류 시간을 유지하며 계획 시작·종료를 늦춘다. 예약 키가 있는 항목과 첫날 고정 교통 시각은 이동하지 않는다. 개인 저장 조정안·완료·비용·예약은 수정하지 않는다.

## 출처와 한계

시간표 입력 38개는 [Mini Tokyo 3D](https://github.com/nagix/mini-tokyo-3d/tree/c708abea8bf05ab56137a50e52c032112b6f9beb/data)의 고정 커밋과 SHA-256으로 검증한다. 신칸센은 [JR 공개 2026년 11월 시간표](https://timetables.jreast.co.jp/2611/timetable-v/001d1p.html), 반대 방향과 개별 열차 페이지 47개에서 상시 운행 열차만 추출한다. 동행 열차의 출발은 개별 페이지의 실제 출발 값을 사용하며 도착 값에 임의 정차 시간을 더하지 않는다. 공식 전체 표는 외부 빌드 캐시에만 두고 사이트에 재배포하지 않는다.

모든 계산은 **참고 시간표**다. 2027년 해당 날짜의 확정 운행, 실시간 지연, 좌석 재고, 운휴를 보장하지 않는다. 사용자가 출발 시각을 바꿀 때 브라우저에서 새 경로를 자동 검색하지도 않는다. 카드의 `최단시간 우선`과 접힌 `계산 기준`에 범위·확인일을 표시한다. 시간표 조회창은 현재 조회 날짜를 별도로 표시하며 신칸센·로프웨이에 가상 카운트다운을 만들지 않는다.

쓰키지–신토미초는 [메트로 환승 안내](https://www.tokyometro.jp/info/tsukiji.pdf), 추가 연결은 `scripts/tokyo-transfer-references.json`의 공식 역 안내를 근거로 한다. 메트로–도에이 할인은 [도에이 운임 안내](https://www.kotsu.metro.tokyo.jp/subway/fare/discount.html)의 지정 환승만 적용한다. 실제 통로 길이나 승강장 번호를 확인했다는 뜻은 아니다.

운임은 검토한 성인 OD 표에서 채운다. IC 기본운임과 별도 특급권·신칸센 승차권을 분리한다. 환승 통합 운임을 중복 합산하지 않고, 스카이라이너는 계속 공란이다. 가격 미검토 OD는 임의 추정하지 않는다. 빠른 경로는 더 비쌀 수 있다.

## 재생성

Node 22 이상, Python 3 필요. 아래 명령은 저장소 루트에서 실행한다. 캐시에는 공개 자료만 보관하며 Git·공개 배포에서 제외한다. API 키나 유료 경로 API는 사용하지 않는다.

```powershell
$env:TOKYO_REPLAN_CACHE='../tokyo-replan-cache'
$env:TOKYO_TIMETABLE_CACHE='../tokyo-timetable-cache'
node scripts/fetch-tokyo-replan-sources.cjs
node scripts/fetch-tokyo-timetable-sources.cjs
node scripts/fetch-shinkansen-references.cjs
python scripts/extract-shinkansen-reference.py
node scripts/build-tokyo-replan.cjs
node scripts/build-tokyo-timetables.cjs
node scripts/build-assistant-offline.cjs
node --test tests/*.test.cjs
node scripts/japan-qa.cjs
```

공식 페이지의 해시가 바뀌면 중단하고 내용·계절별 시간표를 검토한 뒤 입력 매니페스트를 갱신한다. 검증을 끄고 진행하지 않는다. 지도 재생성은 기존 N02·저장 경로 스냅샷도 사용한다.

검증: Node 회귀 테스트 270개, 기존 22일 원본 데이터 무결성 QA, 오프라인 288개 파일 해시 검증. 브라우저에서 15일·두 대체안, 방향 전환, PC/390px 표시를 확인한다. 실기기 센서·2027년 실제 운행·실기기 Safari는 별도 확인이 필요하다.
